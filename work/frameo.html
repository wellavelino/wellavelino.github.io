frameo-dashboard: a fast Home Assistant wall on a cheap photo frame

A Home Assistant dashboard for a cheap Android photo frame, written for what that hardware can actually run. It appears in 1.9 s; Home Assistant's own login page is 80% janky frames on the same device.

01

The problem

A Denver Frameo frame (PFF_1037) is a cheap screen that would make a good wall display, but it has a 1 GHz Cortex-A7, Android 6.0.1 and WebView 107. Standard Home Assistant dashboards are built for far more than that.

02

What I did

I wrote the dashboard around the frame's limits instead of trying to fit a normal web app on it:

Page No framework

Plain ES5 scripts in one scope, because this WebView has no ES modules. The page is bundled inside a small kiosk APK.

Data One websocket

A single connection to Home Assistant using subscribe_entities. The DOM is touched only when a value changes; reconnects back off.

Updates Safe OTA

A manifest lists every file. The update is swapped in only when all of them downloaded, so a failed update leaves the running copy alone.

Tabs cover Home, Forecast, Calendar, Climate, Lights, Music, Recipes, EV and Settings, and the optional ones hide when their entities are not configured. Unit tests run against recorded Home Assistant responses. The kiosk derives from wesbos/photo-frame-dashboard (MIT).

03

The result

1.9 s to appear on the frame
0 janky frames, idle for 30 s (1 frame drawn)
34 stars on GitHub

The measurement that matters is the comparison: Home Assistant's own login page, on the same hardware, is 80% janky frames.

Measured on one device, a PFF_1037 frame.

04

What I'd do next

Measure more devices. The timings come from one frame; other cheap frames and tablets would show how far they carry.

Make setup easier. A first install still needs ADB. Once it is on the frame, page updates arrive over the air.
