Building AI orchestration · Project notes

harness: a planner, an implementer and a worker that hand off through files

A multi-role orchestrator that drives the Claude Code CLI headlessly: one role plans, others do the work, and every step leaves a file you can read.

Role
Solo builder
Year

Stack

harness
01

The problem

One long agent session loses track of a big task: context fills up, mistakes carry forward, and afterwards it is hard to see why anything happened.

02

What I did

I split the work into roles, each running on its own model, and made the filesystem the shared memory:

Plan Tasks as files

The planner writes plan.md and one file per task, with dependencies, verify commands and acceptance criteria.

Execute Fresh sessions

Tasks run in dependency order, each in a new session. On failure the error is fed back for a retry, then the task escalates, then it is marked failed.

Review Verdict, then replan

A reviewer writes reviews/final.md ending in PASS or FAIL. Failures go back to the planner, up to a set number of rounds.

Because each handoff is a file and not a prompt, every step can be inspected after the run. The code is six source files.

03

Where it stands

A working prototype, run from the command line.

It has no tests and no public repository yet.

04

What I'd do next

Add tests. The retry, escalation and replan paths are where a bug would cost the most.

Measure it. Comparing runs against a single session would show whether the roles earn their extra cost.
